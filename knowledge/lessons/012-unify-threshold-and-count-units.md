# 阈值与计数类逻辑要统一单位，且行数统计必须认所有行尾

## 场景
对用户输入做长度/行数判定并据此改变展示（折叠、截断、分页）。

## 问题
粘贴折叠的占位符显示 `[粘贴 1 行]`，而用户明明贴了一大段。三个独立成因：

1. 行数用 `s.split('\n').length` 统计，**不认 `\r`**——只有 `\r` 行尾的内容（旧 Mac 风格 / 部分应用复制出来）被算成 1 行
2. 占位符**无条件**渲染成 `[粘贴 N 行]`，于是**单行长文本**（按字符阈值折叠的）显示成误导性的 `[粘贴 1 行]`
3. 单位不一致：折叠判定用 `s.length`（UTF-16 码元）而显示用 `[...s].length`（码点），含 emoji 时会出现"已折叠但显示字符数小于阈值"

另：原阈值（20 行 / 2000 字符）与实际可见容量脱节，用户实测反馈"太大了，超过 3 行就该收起来"。

## 解决方案
1. 行数统计封装成可单测的纯函数 `countLines()`，同时认 `\n`、`\r\n`、单独的 `\r`
2. 显示按**实际折叠原因**区分——多行 `[粘贴 N 行]`、单行 `[粘贴 N 字符]`
3. 判定与显示**统一用码点**（`[...s].length`）
4. 阈值与**可见容量**对齐（本项目下调为 3 行 / 200 字符，字符阈值取自"固定 3 行窗口在 80 列下约 240 字符"）
