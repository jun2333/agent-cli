# 测试报告"全绿"不等于真实路径可用 —— 断言锁了格式却没锁数值/行为

## 场景
实现阶段自测全绿、独立测试阶段复查也全绿，准备放行收尾时。

## 问题
任务 006 的 testing 阶段给出「54/54 PASS，总体结论通过」，但随后的**独立审查在真实路径上推翻了 3 条 AC**：

1. 工具行「输出 N 行」**恒为 1**（实测 `bash seq 1 40` 显示"输出 1 行"；`src/index.e2e.test.ts:1072` 只锁了**格式** `输出 \d+ 行`，没锁**数值**）；
2. 1000 行截断阈值对 JSON 信封**彻底失效**（实测 2000 行 / 36.9KB 完全不截断）；
3. hook 超时对墙钟**无约束**（AC-45 只用 `sleep 5`，**没有后台子进程**，恰好绕开了被考察的机制——真正触发它需要 `sleep 5 &`）。

三条都不是"用例不够多"，而是**断言没锁住行为**：它们能通过，也能在实现完全错误时通过。

## 解决方案
1. 对**每个数值断言**要求给出真实路径实测，不允许只断言"格式/正则能匹配"；
2. 边界类 AC（阈值、超时、截断）的用例必须**构造真正能触发该边界的输入**——`sleep 5` ≠ `sleep 5 &`，2000 行 ≠ 1000 行；
3. 测试阶段保留"对抗性抽查"环节：对高危 AC 逐条追问「**这个断言如果恒真会怎样**」「把实现去掉它还会过吗」。

## 附加发现（同一次审查的副产品）
testing 阶段自己补了一条实现漏交的断言（"连续两轮请求 system+tools 字节一致"，前缀缓存 44× 的硬约束）——补齐时首版写法失败，恰好**证明该断言此前从未存在**。可见"计划承诺过的断言"也需要有人在收尾时逐条核对是否真的落地。
